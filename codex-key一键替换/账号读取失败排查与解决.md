# CRS 账号读取失败排查（历史问题）

本文保留旧版 Codex CLI 通过 CRS 启动时出现 `account/read failed during TUI bootstrap` 的排查记录。该现象曾见于 0.117.0 附近的版本；升级后的报错应以当前 CLI 的实际日志和请求路径为准。

## 排查顺序

1. 运行 `codex --version`，记录实际使用的 CLI 版本，并确认启动的是预期安装位置的 Codex。
2. 检查 `~/.codex/config.toml`（Windows 使用 `%USERPROFILE%\.codex\config.toml` 或 `CODEX_HOME\config.toml`）：确认 `model_provider = "OpenAI"`、`base_url` 指向正确的 CRS 服务，且 `[model_providers.OpenAI]` 下仍配置 `requires_openai_auth = true`。
3. 确认同一配置目录下存在 `auth.json`，且其中有有效的 `OPENAI_API_KEY`。不要用 `cat`、`Get-Content` 或日志命令输出整个文件，以免泄露 token。
4. 根据当前报错和服务端日志核对实际请求路径、方法及返回状态。若 CRS 缺少对应接口，由服务端补齐兼容性；若返回鉴权错误，核对 token 和服务端权限。

## 旧方案说明

旧文档建议通过 `codex --disable tui_app_server` 或在 `[features]` 中写入 `tui_app_server = false` 处理此错误。当前 Codex CLI 已移除该功能开关，不应继续使用这两种方法。`features.apps = false` 只会禁用连接器，也不能替代账号接口或鉴权修复。

不要为了绕过账号读取而直接删除 `requires_openai_auth = true`，也不要把旧版本回退作为通用修复方法。先确认当前 CLI 与 CRS 的实际接口行为，再处理对应故障。
